## 分類

十個分類同報告上面嘅標籤完全一樣：

[合約](20-qa/合約.md)　[機器設定](20-qa/機器設定.md)　[轉貨](20-qa/轉貨.md)　[補貨](20-qa/補貨.md)　[報價](20-qa/報價.md)　[維修](20-qa/維修.md)　[投訴](20-qa/投訴.md)　[查詢](20-qa/查詢.md)　[會計相關](20-qa/會計相關.md)　[其他](20-qa/其他.md)

分類同關鍵字由 [config/keywords.json](../config/keywords.json) 定義。要加關鍵字改嗰個檔，改完 SOP 呢邊會自動跟。

## 狀態標示

每條 Q&A 都有狀態：

- **已核准** —— 主管審過。可以直接複製俾客戶。
- **草稿** —— AI 由對話紀錄抽出嚟，未經人審。**唔好照抄俾客戶**，要問主管。

## 呢份 SOP 點樣維護

### 三個階段

**A. 挖掘（自動，每星期一次）**

程式掃返 WhatsApp 群組，抽出「客戶問乜、同事點答」，寫入 `data/qa-candidates.jsonl`，狀態 `pending`。

參數（同每日兩次嘅工單掃描分開，唔會影響佢）：

| 參數 | 值 | 原因 |
|---|---|---|
| 每個群組抓幾多則訊息 | **30 則** | 要夠長先睇到「問題 → 回覆 → 客戶確認」成個來回 |
| 略過條件 | **最後一則訊息距今超過 5 日** | 靜咗嘅群組冇新嘢可以抽，抽咗都係重複，慳 API 錢 |
| 頻率 | 每星期一次 | 工單掃描一日兩次，唔可以拖慢佢 |

> 對比：現時嘅**工單掃描**用 `MESSAGE_HISTORY_LIMIT=20`、`SCAN_LOOKBACK_HOURS=168`（7 日），每日 09:00 同 14:00 各行一次。挖掘工作係另一支，唔好改工單掃描嘅參數。

**B. 審核（人手，每星期約 20 分鐘）**

儀表板列出待審清單，逐條揀 **採用 / 修改 / 棄用**。

呢一步唔可以省。**一個錯嘅標準答案，比冇答案更加危險**，因為同事會照住覆客戶。

**C. 發布**

已核准嘅條目寫入 [20-qa/](20-qa/) 對應嘅檔，commit 入 git。同事即刻睇到最新版。

## 私隱規矩（重要）

呢個資料夾會 commit 入 git。入面嘅嘢會**永久留低**，而且所有有 repository 權限嘅人都睇到。

1. **唔可以有真實客戶名、電話、地址、公司名、機器編號。** 一律寫 `[客戶]`、`[電話]`、`[地址]`。
2. **唔可以有具體金額**，除非嗰個係公開價目表上面嘅價。
3. 原始對話紀錄放 `data/`，嗰個資料夾已經被 git 排除，唔會 commit 上去。

發布之前，審核嘅人要負責去識別化（把可以認出邊個客戶嘅細節拿走或者換成方括號）。

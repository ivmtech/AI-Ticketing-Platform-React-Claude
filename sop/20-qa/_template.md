# Q&A 條目格式（範本）

呢一版唔係俾客戶服務同事日常查嘅。呢一版係話你知：一條 Q&A 要點寫。
新增條目時，複製下面整段，貼落對應嘅分類檔（例如 `維修.md`）嘅「常見問題」下面。

---

### Q：客戶點問（用客戶原本嘅講法，唔好改寫成書面語）

**標準回覆**

> 直接可以複製俾客戶嘅字。用得幾實就寫幾實。
> 要填空嘅位用方括號，例如 [日期]、[師傅名]、[金額]。

**回覆之前要查嘅嘢**

- 查咩系統／問邊個／確認咩資料

**唔好講**

- 唔可以承諾嘅嘢（例如具體到場時間、未批嘅折扣）

**幾時要升級**

- 符合呢啲情況就唔好自己覆，照 [../90-escalation.md](../90-escalation.md) 交上去

| 分類 | 優先級 | 狀態 | 最後更新 | 來源 |
|---|---|---|---|---|
| 維修 | 高 | 草稿 | 2026-08-21 | 群組 XXX，2026-08-14 |

---

## 欄位規則

| 欄位 | 可以填 | 意思 |
|---|---|---|
| 分類 | 合約 / 機器設定 / 轉貨 / 補貨 / 報價 / 維修 / 投訴 / 查詢 / 會計相關 / 其他 | 同報告上面嘅標籤一樣 |
| 優先級 | 高 / 中 / 低 | 同報告上面嘅一樣 |
| 狀態 | **草稿** / **已核准** | 草稿＝未經主管審，唔好照抄俾客戶。已核准＝可以直接用 |
| 最後更新 | YYYY-MM-DD | 改咗內容就要更新呢個日期 |
| 來源 | 群組名＋日期，或者「人手撰寫」 | 話你知呢條答案由邊度嚟，方便日後翻查 |

## 三條硬規矩

1. **答案入面唔可以有真實客戶名、電話、地址、公司名。** 一律寫 [客戶]、[電話]、[地址]。
   呢個資料夾會 commit 入 git，入面嘅嘢會永久留低。
2. **一條 Q&A 只答一件事。** 客戶一句問三樣嘢，就拆成三條。
3. **改咗答案，要更新「最後更新」同「狀態」。** 大改要重新變返「草稿」，等主管再審。
